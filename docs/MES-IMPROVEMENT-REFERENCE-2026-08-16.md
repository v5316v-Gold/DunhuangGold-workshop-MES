## 四、平台架构改进方向

### 4.1 实时数据采集层（最大缺口）

**当前状态**：API 是"事后上报"模式（操作员手动 POST）。

**改进架构**：

```
设备 PLC / 仪表
     │  OPC UA / MQTT / Modbus / RS-232
     ▼
边缘网关 (Edge Gateway)
     │  本地缓冲 + 协议适配 + 预处理
     │  (断网 4 小时不丢数据)
     ▼
MES REST API (批量上报 + 实时)
     │  Kafka / Pulsar (流式消息队列)
     ▼
时序数据库 (TimescaleDB / InfluxDB)
     │  自动降采样 (1s/1min/1hour/1day)
     ▼
实时计算引擎 (Flink / Materialize)
```

**关键要点**：
- **边缘网关**（西门子 IOT2050 / 研华 UNO）：车间本地协议转换 + 缓冲，**保证断网不丢数据**
- **时序库**：0.001g 称重 10Hz，一年 1.6 亿条，必须时序库 + 降采样
- **批量上报**：设备 1 秒 10 条，**不能每条 POST**，要 1 分钟批量上报 600 条
- **设备级实时**：工艺参数毫秒级入时序库，做 SPC 和异常告警

### 4.2 数据采集粒度三级

| 层级 | 频率 | 存储 | 用途 |
|------|------|------|------|
| **设备级** | 10Hz (100ms) | 时序库 | 实时监控/告警/SPC |
| **工序级** | 事件驱动 | OLTP (Odoo) | 报工/损耗/质量 |
| **批次级** | 每天/每班 | OLAP (数据仓库) | KPI/趋势/预测 |

> **当前 Odoo 只做了工序级 + 批次级，缺设备级实时层**。

### 4.3 件级全程追踪（WIP 数字化）

- **每个件级 SN 走完所有工序时记录全流程履历**
- **工序间扫码交接**：每道扫码接收 + 扫码发出，自动记录前工序结束/后工序开始
- **数字孪生**：实时看到每一件首饰在哪个工位、什么状态、累计耗时

### 4.4 称重防作弊（行业核心痛点，P0）

- **电子天平直连 MES**（RS-232 → 网关 → MES），操作员无法手动输入
- **防作弊锁**：每次称重前自动锁定 SOP（必须工序状态=开始），称重后 30 秒内自动上传
- **重量校核**：同一件"工序 N 产出"必须 = "工序 N+1 投料"，差 > 0.001g 自动报警
- **视频联动**：称重时同工位摄像头自动拍照存档（5 秒前 + 5 秒后）

### 4.5 AI 视觉质检（最大潜力方向）

- **工位摄像头 → 边缘 AI 模型 → 实时检测**划痕/凹陷/错镶/漏镶
- **训练数据**：从历史"已通过"+"已退货"的件级 SN 图像训练
- **实时告警**：检测到缺陷 → 推送工位平板 → 操作员立即重做
- **每件件级 SN 一张质检图谱**

### 4.6 离线容错

- **工位平板本地 SQLite 缓存**：网络中断时本地保存报工数据
- **断点续传**：网络恢复后批量同步，带冲突检测
- **关键操作降级**：称重等核心功能在离线时仍能用

### 4.7 NGTC 区块链溯源

- **NGTC 联盟链**：每件 SN 的金料批次/工序/质检/印记上链
- **客户扫码验证**：手机扫码 → 链上查证（防伪/防欺诈）
- **司法取证**：链上数据不可篡改

### 4.8 预测性维护

- **振动/温度数据 → 设备健康度模型**
- **预测故障**：剩余寿命 RUL (Remaining Useful Life)
- **自动派单**：健康度 < 阈值 → 自动创建 `gold.maintenance.order`

### 4.9 报表与 BI 深化

- **数据仓库** (ClickHouse / StarRocks)：从 Odoo ETL 出去
- **多维分析**：按款式/班组/设备/时间 切片的损耗/成本/质量
- **预测分析**：金价预测 / 订单交付期预测 / 设备产能预测
- **金价对账**：实时金价 vs 锁价 vs 实际成本 差异报表

### 4.10 主数据治理（BOM/工艺版本化）

- **BOM 版本快照**：订单用的 BOM 即使后续修改也不影响（用 `gold.ecn` 触发版本切换）
- **工艺路线版本**：每个 order 用哪个版本的路线
- **生效日期**：BOM/路线有 effective_from / effective_to

### 4.11 多工厂 / 多车间

- 引入 `res.company` + 多个 `gold.workstation.company_id` 区分
- 跨工厂物料调拨
- 中央调度（哪个工厂生产哪个订单）

### 4.12 主数据安全与合规

- **贵金属账实相符**：每日自动盘点差异分析 → 报警
- **操作审计**：所有动作（特别是金料领用/称重/盘点）必须留痕
- **多级审批**：≥ 100g 旧金回收自动触发 AML 上报
- **数据保留 5 年**（旧金 + 反洗钱法规）

## 五、当前项目实现度评估

| 维度 | 实现度 |
|------|-------|
| 工艺主数据（工序/路线/BOM/模具/蜡模）| 🟢 90% |
| 4M1E 五要素全覆盖 | 🟢 90% |
| 生产后闭环（盘点/入库/回料）| 🟢 85% |
| 金料管理（0.001g + 锁价 + 回收 + 调整）| 🟢 90% |
| 件级 SN（一物一码）| 🟢 80%（WIP 流转弱）|
| 质量（印记+XRF+OCR）| 🟡 70%（缺 AI 视觉 + SPC）|
| 设备（OEE + 心跳 + 维护）| 🟡 65%（缺实时 PLC）|
| 文档/版本（SOP + ECN）| 🟡 60% |
| 数据采集（手工报工）| 🔴 35%（缺边缘层/时序）|
| 预警/告警（损耗/超限/低库存）| 🟡 60%（缺预测）|
| 追溯/合规（件级 + NGTC 字段）| 🟡 55%（缺区块链）|
| 上下游集成 | 🔴 30% |
| BI/决策 | 🟡 50% |

**整体"事无巨细"完成度估算：约 60-65%**

> 核心 MES 流程 + 4M1E + 生产后已闭环，但**实时数据采集、设备集成、AI 视觉、多工厂、上下游集成**是真正"事无巨细"的主要差距。

## 七、最终判断

**贵金属首饰 MES 的"事无巨细"不在 Odoo 业务层，而在 OT 实时层。**

当前项目（Odoo 模块 + ui_preview 动态预览）已经做完**业务流骨架**（4M1E + 生产后 + 金料 + 印记 + NGTC）。要做"事无巨细 + 数据完整采集"，**真正的难点不在 Odoo 里，而在车间 OT 层**：

- 设备协议适配（OPC UA / MQTT 实际接入）
- 边缘网关（断网缓存 + 批量上报）
- 时序数据库（10Hz 设备数据）
- AI 视觉（外观/镶嵌/划痕）
- 区块链（NGTC 防伪）

**如果只能做一个事**：**先做称重防作弊 + 件级 WIP 全程追踪**——"事无巨细"投入产出比最高的两件事，把金料"0 损耗丢失"和"件级 100% 可追溯"做到极致。
